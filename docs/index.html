Humans see exactly what they always saw; agents read clean structure instantly.

The opportunity

PDFs are everywhere, and until now OCR engines and vision models have been extremely powerful tools for extracting data from those rich documents and feeding it into AI workloads. That pipeline works — but it exists for one reason: PDFs were never designed with machines in mind, so every consumer has to reconstruct meaning after the fact.

The same shift is already happening on the web, where sites publish markdown mirrors so agents can read them directly (agent readability, llms.txt). It should happen to other documents too. Let's go to the source and make PDFs agentic-ready by design — simpler (no reconstruction pipeline), safer (exact text, no model guesswork), and more cost effective (zero per-page extraction cost).

How content reaches LLMs today

ApproachExamplesConsiderations
Cloud OCR / document AI AWS Textract, Google Document AI, Azure Document Intelligence Mature and accurate on scans; per-page pricing, layout heuristics, infrastructure to run
Vision & multimodal models GPT-4o / Claude reading page images, Mistral OCR Very flexible — reads anything; token-heavy (every page re-read by a model), cost scales with corpus size
Specialized PDF parsers Adobe PDF Extract API, LlamaParse, Unstructured.io, Marker Better structure awareness; still heuristic — tables and multi-column layouts can come out lossy or reordered
Agentic layer at the source this project Deterministic: exact mirrored text embedded in the file. Zero extraction cost, no third party, works offline. Complements the tools above, which remain ideal for legacy scans
The right tool for the job: scanned archives will always need OCR. But most agentic-era documents are born digital — they pass through a printer driver anyway. Printing them with the agent layer built in means every downstream AI workload skips the extraction step entirely. 
Today:   legacy PDF -> OCR / vision model -> LLM   (per page, every time)

Agentic: Raw content -> PDF + agent.md -> LLM   (free, exact, instant)
👁

Invisible to humans

The agent layer uses standard PDF EmbeddedFiles. Nothing renders on any page; Preview, Acrobat, and every printer output look unchanged.

🤖

First-class for agents

No OCR, no layout heuristics. Agents extract one attachment and get frontmatter, headings, lists, and glossary as plain markdown.

🖨

Printable by anyone

A CLI driver and a CUPS virtual printer mean any app's Print dialog can produce agentic PDFs — no changes to the source application.

🔍

Verifiable

A one-command check reports whether a file carries a conforming layer, which spec version, and its metadata.

Why raw PDFs resist machines

A PDF looks like a document, but inside it is a printing instruction sheet. Text is stored as glyph-drawing commands at explicit canvas coordinates — there are no paragraphs, headings, or tables anywhere in the file. Here is a real content stream from a PDF produced by this project: 

4 0 obj
<< /Length 2451 /Filter /FlateDecode >>
stream
q 1 0 0 1 16.84 0 cm BT 0.0001 Tc 12 0 0 12 0 803.044 Tm /TT1 1 Tf (ACME INDUSTRIES PLC) Tj ET Q
q 1 0 0 1 16.84 0 cm BT 0.0001 Tc 12 0 0 12 0 791.044 Tm /TT1 1 Tf (...) Tj ET Q
…hundreds more lines like this, then…
xref
0 19
0000000000 65535 f 
endtrailer
%%EOF

Everything an agent needs to understand the page is missing from those bytes:

  • No reading order. "803.044" and "791.044" happen to be consecutive lines here; in a two-column paper, successive instructions jump between columns.
  • No semantics. Nothing distinguishes a heading from a footnote — both are just (text) Tj at some position in some font.
  • No structure. A table is dozens of independently drawn text runs plus ruled rectangles; a chart is opaque vector paths or pixels.
  • Compression. Content streams are Flate-compressed binary — raw byte scanning sees nothing useful at all.

This is precisely why the extraction industry exists, and why embedding the structured layer alongside the visual pages is the cheaper, safer path.

How it works

An agentic PDF is a normal PDF plus a set of named attachments defined by this specification. The attachments ride along inside the file:

AttachmentStatusContent
agent.mdrequiredMarkdown mirror of the document with YAML frontmatter (the primary agent interface)
agent.htmlrecommendedHTML rendering of the mirror, with <meta> / OpenGraph tags
llms.txtoptionalIndex of related documents, for bundles and archives
┌──────────────────────────────────────────────┐
│  report.pdf                                  │
│                                              │
│  Pages 1–12   ← what humans see (unchanged)  │
│                                              │
│  EmbeddedFiles:                              │
│    ├── agent.md    ← what agents read        │
│    ├── agent.html  ← HTML mirror             │
│    └── llms.txt    ← bundle index (optional) │
│                                              │
│  Info dict: Title, Subject,                  │
│             AgentReadability, CanonicalSource│
└──────────────────────────────────────────────┘

Design principles

  • Zero visual change. If printing or viewing the PDF would differ in any way from a non-agentic copy, the implementation is broken.
  • One extraction, full fidelity. Everything an agent needs must be in agent.md. It should never need to fall back to text scraping.
  • Standard mechanisms only. PDF 1.7+ EmbeddedFiles and the Info dictionary — no proprietary sidecars or network calls.
  • Degradable. Removing the attachments yields a perfectly valid legacy PDF.
  • Honest mirrors. The markdown must mirror actual page content, not summaries or interpretations.

Quick-start checklist

Produce a conforming document with:

# print any convertible file into an agentic PDF — everything is
# extracted automatically from the raw data; no flags needed:
agentic-pdf print docs/demo/report.txt -o report.pdf

# real-world stress test: a 77-page Federal Reserve report full of charts
agentic-pdf print docs/demo/fed-monetary-policy-report-july-2026.pdf

# chart + table demo: table becomes markdown, figure caption is preserved
agentic-pdf print docs/demo/acme-q2-results.pdf

# verify the layer
agentic-pdf check report.pdf

# hand the markdown straight to an LLM
agentic-pdf read report.pdf --raw | llm "summarize this"
  • agent.md attachment present, MIME type text/markdown
  • Frontmatter includes title, description (50+ chars), doc_version, last_updated, generator
  • Body contains # Title, ## Summary, ## Content, ## Sitemap, ## Glossary sections
  • Tabular content mirrored as markdown tables in ## Tables; figure/chart captions listed in ## Figures with page references (when the source contains them)
  • Info dictionary sets AgentReadability = agentic-pdf-spec/1.1
  • Canonical source recorded via frontmatter canonical and Info key CanonicalSource
  • Visual pages byte-for-byte equivalent in appearance to a non-agentic print
  • (Recommended) agent.html mirror attached with meta description + og tags

Layer structure

Section headings are load-bearing: agents use them to route queries and quote precisely. Every conforming agent.md contains at least these H2 sections, in order:

SectionContents
# <Title>Single top-level heading matching the frontmatter title
## SummaryThe description — enough context to decide relevance without reading further
## Table of ContentsLinks/list of major sections (when 2+ exist)
## ContentThe mirrored document body, structured into headings, paragraphs and lists; per-page anchors (_​(p.N)_) preserve provenance back to visual pages
## TablesDetected tabular blocks rendered as markdown tables with captions and page refs — e.g. a printed financial table comes out as | Segment | Revenue | YoY | rows. Best-effort: chart axis labels and legends are filtered. Optional — present when tables are detected
## FiguresCaptions of figures/charts/exhibits with page refs. Chart pixels stay in the visual layer; the captions give agents provenance and let them tell readers which page to view. Data labels printed on charts (percentages, values) surface in ## Content. Optional
## SitemapInventory of this file, sibling attachments, and the canonical PDF
## GlossaryRecurring terminology and acronyms with occurrence counts, resolving ambiguity
Fidelity rule: the Content section must be derivable from the rendered pages. Generators may restructure (headings, bullets, paragraphs) but must not omit substantive text or add commentary.

Metadata & discovery

Discovery follows the web spec's principle that agents shouldn't have to guess how to consume a resource — the document itself advertises its layer:

  • The presence of the AgentReadability Info key is the machine-checkable declaration of conformance.
  • Keywords include agent-readable so corpus-wide indexing can find agentic files.
  • Bundles SHOULD provide llms.txt listing member documents and their relationships.
  • The canonical/`CanonicalSource` pair lets agents deduplicate against web or filesystem sources, mirroring `` semantics.

Transport & content negotiation

When an agentic PDF is served over HTTP (by the bundled viewer or any static host), conforming endpoints behave like the web spec's markdown mirrors:

RequestResponse
GET /doc.pdfThe original visual PDF, application/pdf
GET /agent.mdRaw layer, text/markdown; charset=utf-8, with Link: </doc.pdf>; rel="canonical"
GET /agent.htmlHTML rendering of the layer
GET / + Accept: text/markdownRaw layer — content negotiation, as if the PDF were a webpage with a .md mirror

Verification & scoring

The normative specification is SPEC.md. Score a document the way the web spec scores a site — passed checks over total checks: 

score = round(passed checks / total checks × 100)
CheckWeight
agent.md present and non-emptyrequired — score is 0 without it
All required frontmatter fields present; description ≥ 50 charshigh
Required H2 skeleton presenthigh
AgentReadability Info key matches this spec versionmedium
Canonical source declared (frontmatter and/or Info)medium
agent.html mirror present with meta tagslow
Glossary covers detected terminologylow
Tables rendered as markdown; figure captions preserved with page refslow (bonus)

Ratings: 90–100 excellent · 70–89 good · 50–89 fair · below 50 needs work.

Verify now: drop any PDF into the viewer — it renders the visual pages, extracts agent.md client-side, and shows the badge agentic layer ✔ only for conforming files. Or run agentic-pdf check file.pdf.

Tooling

The reference implementation is a single Go binary (~11 MB) with no runtime dependencies: 

# install
git clone https://github.com/msanvido/agentic-pdf && cd agentic-pdf
make build            # → bin/agentic-pdf (also: make cross for all platforms)

# local viewer at http://localhost:4173/?file=doc.pdf
agentic-pdf view memo.pdf

All examples use files that ship in the repository under docs/demo/ — including a real, chart-heavy 77-page Federal Reserve Monetary Policy Report (public domain) as a stress test.

Automatic printing

No manual step is needed at print time — the driver extracts everything (title, summary, timestamps, canonical source) from the raw document data.

PlatformSetupWorkflow
macOS sudo agentic-pdf install-backend Any app → Print → Agentic PDF Printer → agentic PDF lands in /Users/Shared/Agentic-PDF
Windows agentic-pdf install-watch (once) Any app → Microsoft Print to PDF → save into Documents\Agentic-Spool → agentic PDF appears in Documents\Agentic-PDF with a toast notification
Linux agentic-pdf install-watch Drop any PDF into the spool folder; a systemd user service converts it automatically

Windows does not permit unsigned third-party print drivers, so the watcher pairs with the built-in Microsoft Print to PDF writer — same one-print-step experience, zero driver signing. The watcher also skips files that already carry an agent layer, so round-trips are safe.

Non-PDF input is converted through the platform's CUPS filter chain; PDF input passes through untouched except for the added layer.

For agent authors

If you are an AI agent reading this site, consuming an agentic PDF takes one step:

# extract the EmbeddedFile named "agent.md" (MIME text/markdown):
agentic-pdf read doc.pdf --raw

# no CLI? any PDF library works — e.g. Python:
python -c "import pikepdf; \
  print(pikepdf.open('doc.pdf').attachments['agent.md'])"

Trust the frontmatter for citation metadata (title, last_updated, canonical), use the ## Content section for retrieval, and treat the visual pages as the human-facing rendering of the same information.
